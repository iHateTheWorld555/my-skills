# 单篇文档规则

强制度标注同 [句子层规则](sentence.md)。本篇规定文档的目的、结构与检查流程。

## 一、明确目的与范围 [MUST]

一篇文档服务一个主要意图。将标题改写成问题，各二级章节都应帮助回答；无关内容删除或另成文档并链接。

开头说明主题、覆盖范围、必要前置知识。仅在读者可能误解时说明不覆盖的内容，并链接替代文档。写作中内容与范围不符时，调整内容或范围声明。

标题按主要目的命名：以操作为主时用任务式标题，即使正文包含概念介绍。

## 二、标题结构（阮一峰、zh-style-guide）[MUST]

- 最多四级，从一级逐级递增，不跳级；三级下的简单并列内容优先用列表。
- 同一上级下的同级标题至少两个；下级标题不与上级同名。
- 标题后先有正文，再设下级标题。
- 同类型的同级标题结构一致；任务与概念章节分别按内容命名。
- 标题概括本节，不用复杂标点组合；末尾不用点号，不解释缩写，不放链接或序号。
- 列表下不嵌套标题。

标题可用名词短语、主题词加动词、动词加主题词、定语加主题词、介词加定语加主题词。任务章节用动宾短语，不写“实例的创建”等名词化标题。

| 内容类型 | 标题形式 | 示例 |
|---|---|---|
| 任务：怎么做 | 动宾短语 | 创建实例、配置鉴权 |
| 概念：是什么 | 名词短语 | 实例类型、鉴权机制 |

同篇可包含两类章节，但须共同服务文档主要目的。

## 三、段落组织（阮一峰、zh-style-guide、Google）

- 一段一主题，50–200 字为佳，不超过 250 字。[MUST]
- 中心句和重要信息优先放段首；超过 5–6 句时检查是否需要拆分。单句已完整表达一个主题时可独立成段。[SHOULD]
- 开头给出关键结论，首段应能独立说明主题，再补充细节。[MUST]
- 概念说明后紧接应用示例；暂不需要的历史或术语细节放文末或链接引用。[SHOULD]
- 网页文档段落顶格，段间空一行；使用陈述语气。[MUST]

## 四、先写大纲 [MUST]

长文档动笔前，先回答受众四问：谁读、为何读、已知什么、读后应掌握什么。再用一句话确定主题，列出大纲；每项只包含一个概念或任务。请用户确认后写正文，定稿时对照大纲检查。

开头可按以下结构组织，避免重复主题与范围：

```markdown
# 标题

主题与关键结论。

必要的范围和前置知识；如需说明不覆盖内容，附替代文档链接。

## 正文第一节

正文。
```

## 五、内容元素

### 提示 [SHOULD]

按用途分为“危险、警告、注意、说明、建议”。每条不超过 4 行，不在提示内放表格或图形。数据丢失等强警示可用感叹号。

### 图片、代码与界面

- 图片文字用中文，附替代文本。[SHOULD]
- 代码块前后空行，按上下文缩进，注释符遵循对应语言。[SHOULD]
- 代码用等宽格式；界面元素可加粗。[MAY]

### 音视频示例 [SHOULD]

附简短说明，明确比较对象与观察内容，如“比较处理前后的语音可懂度”。

## 六、定稿检查 [MUST]

1. 运行 `scripts/check.py`，逐项判断提示并修正问题，不机械替换。
2. 通读，删除不影响含义的字词句，再朗读检查。
3. 操作型文档按目标读者的已知条件检查：前提完整、每步可执行。
4. 对照范围与大纲，删除无关内容，确认结构与目的相符。
