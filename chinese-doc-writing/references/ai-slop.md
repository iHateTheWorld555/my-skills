# 专业表达规则

适用于回复与文档。以准确、清晰、克制为准；精简不得损失事实、条件或不确定性。

## 一、直接陈述 [MUST]

- 直接写结论与依据，删掉“先说结论”等引导语。
- 仅在纠正真实误解或区分易混概念时用“不是 X，而是 Y”，不虚设观点再反驳。
- 删除表演式转折、自问自答、假装顿悟、警句式总结和自我赞扬。
- 汇报实际改动、验证结果和未解决项，不反复宣告完成。不虚构检验过程。
- 在授权范围内，做法明确就执行；仅在关键条件或用户偏好缺失时提问。

## 二、用具体表述替代比喻 [MUST]

技术说明直接写对象、动作、原因和结果。删除不增加解释力的拟人、物理动作比喻及夸张措辞。

| 避免 | 改为 |
|---|---|
| 流程卡住了 | 导入失败，原因是…… |
| 把参数硬塞进去 | 向函数传入参数 |
| 问题藏在数据里 | 中文样本缺少该字段 |
| 用重试兜底 | 请求失败后重试，最多 3 次 |
| 把配置钉死 | 将配置固定为…… |
| 这次是大胜利 | 指标由 X 提高到 Y |
| 静态门 / 长程门 / 过 xx 门 | 静态检查 / 长程训练 / 达到 xx 水平 |
| quality gate | 还原成具体评测名，如「fixed-64 评测」 |
| 硬门槛 / 卡门槛 | 要求 / 条件 / 不再要求 X |
| 对齐契约 / 接口合同 | 约定 / 接口定义 |

「门、合同、契约」类包装词单独说明：把判定步骤或约定包装成拟物名词，不增加信息。「门」暗示一扇过了就完事的闸，实际只是评测节点或淘汰条件；「契约/合同」说的就是约定。中文有现成说法，直接还原成实际动作或对象。同类包装词还有：制品（还原为「文件」「产物」）、工件、落地页（还原为文档实际名称）、心跳、门禁（还原为具体检查）。豁免：有明确定义的技术术语不换，如 gating mechanism（门控）、法律语境的合同、K8s/CI 系统内建的工件概念；不按词表机械替换。

示例中的原因、次数和数值须按实际情况填写，不得为改写补造事实。
保留有明确定义的专业术语，如分布漂移、回归、数据对齐、信号与噪声；不要按词表机械替换。

## 三、用依据支持判断 [MUST]

- 用具体结果替代“优雅、到位、更稳”等笼统评价。
- 区分事实、推断和建议；未验证的原因写为假设，不称为“根因”。
- 说明比较对象、适用条件和限制；不作无依据的绝对化判断。
- 调试说明按需要列出现象、检验和结论，不写成悬疑故事。

## 四、按内容组织格式 [SHOULD]

- 结论优先。并列项用列表，操作顺序用编号，对比用表格；不凑数量，不为短句另设标题。
- 加粗仅用于必要提示，不逐项加粗标签，不用表情符号装饰结构。
- 按语义使用标点，不用破折号制造转折或强调。

## 五、自检

删除无信息增量的句子，核对术语、事实和结论范围。写文档时另查 [文档精简规则](ai-slop-doc.md)。
`scripts/check.py` 的词频和密度阈值仅作筛查提示；须结合语境判断，不作为写作配额或质量结论。
